ANALYSIS SUMMARY
================================================================================

The MovieGenius database consists of 17 main tables organized into 4 categories:

1. CORE TABLES (3)
   - movies: Master table with 35K+ records, TMDB integration, processing flags
   - movie_analyses: 21,275+ Claude-generated analyses with JSONB content
   - enhanced_why_watch: Binary YES/NO recommendations with 3 reason objects

2. BROWSE SYSTEM TABLES (6)
   - browse_lists: 827+ curated collections with polyhierarchical organization
   - browse_facets: 50+ facet categories (genre/theme/location/time/contributor/technique/mood)
   - list_movies: 2000+ movie-to-list relationships with relevance scoring
   - list_facets: Facet-to-list relationships with hierarchical support
   - browse_list_jobs: Batch processing job tracking
   - browse_list_engagement: User interaction tracking for analytics

3. SUPPORTING TABLES (5)
   - persons: 39,606 cast/crew registry with numeric IDs
   - movie_contributors: 100K+ crew index linking movies to persons
   - movie_lists: Legacy list system (predates browse_lists)
   - movie_list_items: Legacy list-to-movie junction
   - list_analyses: AI-generated list descriptions
   - episodes: Educational content (now archived)

4. ADMINISTRATIVE TABLES (4)
   - error_logs: Error tracking
   - error_alerts: Critical alerts
   - performance_metrics: Query/system metrics
   - deployments: Deployment tracking

BONUS: 6 Pre-built Views
   - content_status_dashboard: Overall completion statistics
   - movies_needing_analysis: Content gaps report
   - movies_needing_links: Link processing status
   - movies_needing_slugs: Missing URL slugs
   - movies_needing_review: Quality issues
   - facet_hierarchy: Browse facets with hierarchical paths

================================================================================
KEY FINDINGS
================================================================================

SCHEMA CHARACTERISTICS:
✓ JSONB fields for flexible content storage (claude_response, reasons, metadata)
✓ UUID primary keys for distributed systems (browse tables)
✓ Status tracking flags with hierarchical progression (analysis_ready → display_ready)
✓ Comprehensive indexing for performance (compound, partial, GIN trigram)
✓ Foreign key constraints with CASCADE delete for referential integrity
✓ Trigger functions for automatic metric maintenance
✓ Timestamps on all tables for audit trails

DATA FLOW PATTERNS:
1. Movies flow: Created → TMDB enriched → Analyzed → Links processed → Slugs generated
2. Browse flow: AI generates lists → Assigns movies by relevance → Organizes by facets
3. Contributors: Auto-extracted from movie_analyses keyElements → Stored in movie_contributors

TABLES QUERIED MOST FREQUENTLY:
- movies (every API call uses this)
- movie_analyses (for content display)
- enhanced_why_watch (for recommendations)
- browse_lists (for collection browsing)
- browse_facets (for facet navigation)
- movie_contributors (for person pages)

SCALING NOTES:
- Compound indexes on (movie_id, analysis_type) and (title, year) prevent full table scans
- Status flags allow targeted queries (e.g., "show only display_ready movies")
- Partial indexes on boolean flags reduce index size and improve query speed
- GIN indexes on JSONB fields enable complex nested searches
- Views aggregate common query patterns for application consistency

================================================================================
STRUCTURE BY TABLE
================================================================================

MOVIES TABLE (Master Table)
├─ Identification: id (int), tmdb_id (int), title, year, slug
├─ TMDB Data: official_title, release_date, poster_url, streaming_data (JSONB)
├─ Processing Pipeline Flags: analysis_ready, links_processed, slug_generated
├─ Quality Tracking: validation_passed, quality_score (0-100), requires_review
├─ Failure Recovery: last_failure_reason, failure_count, last_failure_at
└─ Timestamps: created_at, updated_at, analysis_ready_at, links_processed_at, etc.

MOVIE_ANALYSES TABLE (Content Storage)
├─ References: movie_id (FK to movies)
├─ Analysis Type: page_analysis, enhanced_analysis, etc.
├─ Content: claude_response (JSONB with raw_content, keyElements, validation_report)
└─ Tracking: created_at, updated_at

ENHANCED_WHY_WATCH TABLE (Recommendations)
├─ References: movie_id, tmdb_id (dual lookup optimization)
├─ Recommendation: YES or NO
├─ Reasons: Array of 3 reason objects with strength scores (JSONB)
├─ Metadata: cost, processingTime, model, version (JSONB)
└─ Tracking: created_at

BROWSE_LISTS TABLE (Collections)
├─ Identity: id (UUID), title (UNIQUE), description
├─ AI Data: concept_analysis (JSONB), ai_confidence (0.0-1.0)
├─ Metrics: total_movies, avg_relevance_score
├─ Engagement: view_count, click_through_rate, user_rating
├─ Status: active, draft, archived, merged
└─ Generation: generation_prompt_version, created_at, updated_at

BROWSE_FACETS TABLE (Taxonomy)
├─ Identity: id (UUID), name, facet_type
├─ Hierarchy: parent_facet_id (self-referential)
├─ Display: display_name, description, ui_color, ui_icon, display_order
├─ Metrics: list_count, movie_count, engagement_score
└─ Types: genre, theme, location, time, contributor, technique, mood

PERSONS TABLE (Cast/Crew)
├─ Identity: id (SERIAL), name
├─ Design: Simple numeric ID, allows duplicate names, no deduplication
└─ Tracking: created_at

MOVIE_CONTRIBUTORS TABLE (Credits Index)
├─ References: movie_tmdb_id, person_id, person_name
├─ Role: director, writer, star, cinematographer, composer
├─ Unique: (movie_tmdb_id, person_id, role)
└─ Tracking: created_at

EPISODES TABLE (Educational Content - Archived)
├─ Structure: theme_id, series_id, episode_id (composite unique)
├─ Content: title, subtitle, content (JSONB), hero_image
├─ State: locked (prevents regeneration), locked_by, locked_at
└─ Tracking: generated_at, version, created_at, updated_at

================================================================================
QUERY PATTERNS (DOCUMENTED)
================================================================================

Complete movie lookup with all related data:
  SELECT m.*, ma.claude_response, eww.recommendation, eww.reasons
  FROM movies m
  LEFT JOIN movie_analyses ma ON m.id = ma.movie_id
  LEFT JOIN enhanced_why_watch eww ON m.tmdb_id = eww.tmdb_id
  WHERE m.tmdb_id = $1

Browse list with all associated data:
  SELECT bl.*, array_agg(m.title), array_agg(lm.relevance_score)
  FROM browse_lists bl
  LEFT JOIN list_movies lm ON bl.id = lm.list_id
  LEFT JOIN movies m ON lm.movie_id = m.id
  WHERE bl.id = $1
  GROUP BY bl.id

Content completion status:
  SELECT * FROM content_status_dashboard

Movie contributors with person details:
  SELECT p.name, mc.role
  FROM movie_contributors mc
  JOIN persons p ON mc.person_id = p.id
  WHERE mc.movie_tmdb_id = $1

RECOMMENDATIONS
================================================================================

FOR DEVELOPERS:
✓ Use indexed columns in WHERE clauses (tmdb_id, title+year, analysis_ready)
✓ Reference /docs/DATABASE_QUICK_REFERENCE.md for common queries
✓ Extract JSONB fields with proper syntax (->> for text, -> for objects)
✓ Use views for standard queries instead of hand-writing complex joins
✓ Always use UPSERT pattern for idempotency (INSERT ... ON CONFLICT)

FOR DATABASE ADMINS:
✓ Monitor query performance using pg_stat_user_indexes
✓ Rebuild indexes monthly for high-write tables: REINDEX INDEX CONCURRENTLY
✓ Run VACUUM ANALYZE weekly to update statistics
✓ Use CASCADE DELETE carefully to avoid unexpected data loss
✓ Test migrations on staging before production deployment

FOR NEW FEATURES:
✓ Extend movies table with IF NOT EXISTS clauses (no DROP)
✓ Create CONCURRENT indexes to avoid table locks
✓ Add triggers for automatic metric updates
✓ Use UUID for new distributed tables, SERIAL for simple IDs
✓ Document JSONB structures inline in schema
